# 검수 에이전트 (선택)

완성된 프레임을 보고 **무엇이 어색한지** 짚는다.
이미지 첨부가 되는 에이전트에게 맡긴다 (codex 는 `-i` 로 이미지를 받는다).

## 받는 것

- 렌더된 프레임 6~8장 (시점을 흩어서)
- 장면표와 사운드 설계
- 사용자가 느낀 점 (있다면)

## 보는 것

1. **의미심장한 문장이 증거 자리를 차지하고 있는가**
   이게 가장 흔한 실패다. 교훈을 읽히고 있으면 지적한다
2. **관객이 한 번이라도 틀리게 되는 구간이 있는가**
   없으면 어디에 넣을 수 있는지 제안한다
3. **글자 넘침·겹침**
4. **비유 반복, 결론 선행 노출**
5. **숫자에 맥락이 붙어 있는가**
6. **효과음이 과한가** — 전부 강조하면 아무것도 강조되지 않는다

## 답하는 형식

```markdown
1) 가장 큰 문제 하나 — 왜 어색한지 한 문단

2) 화면에서 고칠 점 5개 — 각 '문제 - 수정안' 한 줄

3) 소리 — 음악 성격이 소재에 맞는가. 아니면 어떤 조건이어야 하는가

4) 효과음 — 빠진 것, 과한 것
```

칭찬과 요약을 쓰지 않는다. 문제만 적는다.
들을 수 없는 것(실제 음악의 좋고 나쁨)은 **판단할 수 없다고 밝힌다.**
수치(음표 밀도, 주파수)는 "말을 안 가린다"는 증명이지 "이야기에 맞다"는 증명이 아니다.
